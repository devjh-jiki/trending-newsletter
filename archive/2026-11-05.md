### 🔎 핵심

Auto Ontology는 데이터베이스와 데이터 소스의 메타데이터로부터 자동으로 비즈니스 용어, SQL 속성, 테이블 관계를 추출하여 온톨로지를 생성한다. 생성된 온톨로지는 인증된 정의와 데이터 계보(lineage)를 기반으로 자연언어 질문을 SQL로 변환하고 검증함으로써 정확한 쿼리 실행과 추적 가능한 결과를 보장한다. MCP, REST API, CLI를 통해 에이전트에 노출되며 사용자 수정과 학습 피드백이 온톨로지 품질을 지속적으로 개선하는 구조다.

### 🎯 활용 사례

- 데이터 분석 팀 — 여러 소스의 정의가 불일치할 때 metrics와 entities의 일관된 의미를 확보하고, 에이전트가 신뢰할 수 있는 응답을 자동으로 생성하도록 함
- BI/분석 에이전트 개발자 — 자연어로 입력받은 사업 질문(예: "6월 펜실베니아 USB 드라이브의 수익")을 자동으로 정확한 SQL과 함께 생성하고 answerability 검사로 데이터 한계 명시
- AI 시스템 운영팀 — PostgreSQL, Snowflake, Databricks 등 10개 데이터 소스를 연결하여 중앙 의미 카탈로그로 관리하고, 웹 UI와 API를 통해 정의 검증·수정·모니터링

## 2. [max-sixty/worktrunk](https://github.com/max-sixty/worktrunk)(Rust) ⭐11,199 (+531)

> Git 워크트리 관리를 단순화하고 AI 에이전트의 병렬 실행을 지원하는 CLI 도구

### 🔎 핵심

Git의 기본 워크트리 기능은 강력하지만 UX가 불편한 문제를 해결한다. Worktrunk는 세 가지 핵심 명령어(`switch`, `list`, `merge`, `remove`)로 워크트리를 브랜치만큼 쉽게 다룰 수 있게 만든다. 브랜치명으로 워크트리를 참조하고 경로는 자동으로 계산되므로, 여러 병렬 작업을 관리할 때 명령어 입력을 크게 줄일 수 있다. 또한 자동화 훅, LLM 커밋 메시지 생성, 빌드 캐시 공유(CoW), CI 상태 표시, PR 체크아웃 등의 기능을 제공한다.

### 🎯 활용 사례

- AI 에이전트(Claude Code 등) 운영자 — 5~10개 이상의 병렬 에이전트를 동시에 실행할 때 각 에이전트가 독립적인 워크트리에서 작업하도록 관리하고, 자동화 훅으로 환경 설정을 일괄 처리
- 다중 기능 개발팀 — `wt list`로 모든 진행 중인 브랜치의 상태(스테이징, 커밋 상황, 원격 추적 등)를 한눈에 확인하고, `wt merge`로 로컬 병합 전 과정을 자동화
- 소프트웨어 개발자 — 빌드 캐시(node_modules, target/ 등)를 여러 워크트리에서 공유하여 반복 빌드를 줄이고, 훅으로 개발 서버나 의존성 설치를 자동으로 실행

gstack은 제품 기획에서 배포까지 전체 소프트웨어 개발 프로세스를 자동화하는 에이전트 스킬 모음이다. `/office-hours`로 제품 기획을 다시 프레이밍하고, `/plan-ceo-review`, `/plan-eng-review`, `/plan-design-review` 등으로 각 분야별 검토를 거친 후, 코드 작성 → `/review` → `/qa` → `/ship`을 통해 프로덕션 배포까지 진행한다. 설계 문서, 테스트 계획, 보안 감사 등 각 단계의 산출물이 다음 단계로 자동 전달되며, 특히 CI를 통과하지만 실제 환경에서 터지는 버그를 찾아 자동 수정한다. 실제 브라우저로 테스트하고, 브랜치별 동작 변화를 추적하며, 보안/성능/DX 검사를 자동화한다.

### 🎯 활용 사례

- 기술 창업자와 CTO — 혼자서 또는 작은 팀에서 제품 아이디어를 빠르게 검증하고 프로덕션까지 배포할 때
- 엔지니어링 매니저와 스태프 엔지니어 — 코드 리뷰, 테스트 커버리지, 보안 감시, 릴리스 프로세스를 자동화하며 팀의 표준을 강제할 때
- AI 에이전트 개발 팀 — OpenClaw, Hermes, Cursor, Codex 등 여러 에이전트 플랫폼에 걸쳐 일관된 개발 프로세스를 유지하고 싶을 때
