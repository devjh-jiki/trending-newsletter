## 1. [semantica-agi/semantica](https://github.com/semantica-agi/semantica)(Python) ⭐4,046 (+967)

> AI 에이전트를 위한 그래프 기반 컨텍스트 및 의사결정 인프라로, 엔터프라이즈 데이터에서 지식 그래프를 구축하고 완전한 감시 추적과 함께 인과 추론을 실행한다.

**무엇인가**

Semantica는 LLM, 벡터 저장소, 에이전트 프레임워크 아래에 앉는 결정적 인프라 계층이다. 엔터프라이즈 데이터(파일, 웹, 데이터베이스, Databricks, Snowflake 등)를 수집하여 구조화된 지식 그래프로 변환하고, 이를 기반으로 규칙 기반 추론, 의사결정 기록, W3C PROV-O 감시 추적을 제공한다.

핵심 작동 방식은 다음과 같다: (1) 다중 소스에서 데이터 수집 및 파싱 (2) 엔티티 및 관계 추출, 충돌 감지 및 중복 제거 (3) 지식 그래프 구축 (4) SPARQL/Datalog 기반 추론 엔진, SHACL 온톨로지 검증 (5) 모든 의사결정을 첫 번째 클래스 그래프 노드로 기록하고 인과 관계 연결 (6) RDF/JSON-LD/Parquet 등 다양한 형식으로 내보내기.

RDF 및 LPG(Labeled Property Graph) 백엔드를 모두 지원하며(Oxigraph, Blazegraph, Neo4j, FalkorDB 등), 벡터 저장소(FAISS, Qdrant, Pinecone 등)와 통합되어 하이브리드 검색을 지원한다. MCP 서버, REST API, CLI, 에디터 플러그인 등 다양한 인터페이스를 제공하고, Agno 프레임워크와 네이티브 통합되어 다중 에이전트 간 공유 컨텍스트를 가능하게 한다.

**어디에 쓰나**

규제 산업의 AI 의사결정 감사: 금융(대출 심사, 사기 탐지, AML 규정 준수), 의료(임상 결정 지원, 약물 상호작용 그래프), 법률(증거 기반 연구, 계약 분석), 정부·국방(정책 결정 기록, 기밀 정보 관리)에서 AI 결정을 감시자(regulator)가 수용할 수 있는 형식(PROV-O)으로 추적 가능하게 만든다.

데이터 거버넌스가 필요한 조직: Databricks Unity Catalog나 Snowflake 웨어하우스에 이미 있는 테이블을 제3자 SaaS로 내보내지 않고도 지식 그래프로 변환하려는 데이터 플랫폼 팀. 온프레미스 배포만 가능하고 데이터 반출 불가인 국방/정부 기관.

복잡한 다중 소스 데이터 통합: 충돌하거나 모순된 사실이 자동으로 감지되고 중복이 병합되지 않은 채 노이즈가 되는 것을 방지해야 하는 상황. 엔티티 해상도, 관계 추출, 온톨로지 관리가 필요한 대규모 지식 그래프 구축.

의사결정 지능이 필요한 에이전트: 선례 검색, 인과 관계 추적, 결정 영향 분석 등 단순 임베딩 유사성 검색을 넘어 구조화된 맥락과 추론이 필요한 경우.

**살펴볼 점**

README에서 명시된 제약 및 전제 조건:

1. ReteEngine의 알파 노드 조건 매처가 의도적으로 단순화되어 있으므로, 프로덕션 규정 준수 게이트에 연결하기 전에 match_patterns() 출력을 실제 규칙 집합과 검증해야 함.

2. 프로덕션 배포 시 Databricks/Snowflake 자격증명을 환경 변수나 시크릿 매니저를 통해 관리해야 함(코드에 하드코딩 금지).

3. ContextGraph.to_dict()의 {"nodes", "edges"} 형태와 RDFExporter가 기대하는 {"entities", "relationships"} 형태가 다르므로, 내보내기 전 데이터 구조 변환 필요.

4. 프로덕션 규모 이상에서는 로컬 pip install 대신 Docker/Kubernetes 배포 권장, 지속형 LPG 그래프 저장소(Neo4j/FalkorDB/Apache AGE/AWS Neptune) 및 호스팅된 벡터 저장소 백엔드(Qdrant/Pinecone) 구성 필요.

5. 일부 모듈(DuckDB, Elasticsearch, Google Drive, MongoDB 등)이 최상위 semantica.ingest 네임스페이스에서 재내보내지지 않으므로 직접 import 필요.

6. 성능 벤치마크는 v0.5.0 기준 118,000 노드 프로덕션 그래프에서 측정되었으며, 실제 결과는 하드웨어, 데이터 집합 토폴로지, 백엔드 선택에 따라 변함.

기술적으로는 Chrome 브라우저의 CDP(Chrome DevTools Protocol) 모드를 사용하여 기존 브라우저 인스턴스에 연결하고, 로그인 상태를 유지한 채 데이터를 수집합니다. JavaScript 역분석이 필요 없으며, 보존된 로그인 상태와 쿠키를 활용해 서명 파라미터를 획득합니다. 데이터는 CSV, JSON, JSONL, Excel, SQLite, MySQL 등 다양한 형식으로 저장 가능합니다.

적합한 사용자는 개발자, 데이터 과학자, 마케팅 전문가, 학생 등으로, 개인 학습 및 연구 목적의 기술 개발자가 주요 대상입니다.

## 10. [firecrawl/firecrawl](https://github.com/firecrawl/firecrawl)(TypeScript) ⭐165,015 (+815)

> 웹에서 대규모로 검색, 스크래핑, 상호작용을 수행하는 API 서비스. 마크다운, 구조화된 JSON, 스크린샷 등 LLM 친화적 형식으로 웹 데이터를 추출합니다.

**무엇인가**

Firecrawl은 웹 데이터 추출을 위한 통합 API 플랫폼입니다. 핵심 기능은 세 가지입니다: (1) Search - 웹 검색 후 결과 페이지의 전체 콘텐츠 반환, (2) Scrape - 임의의 URL을 마크다운, HTML, 스크린샷, 구조화된 JSON으로 변환, (3) Interact - 페이지를 스크래핑한 후 AI 프롬프트나 코드로 클릭, 스크롤, 입력 등의 상호작용 수행. 추가 기능으로는 Agent(AI가 자동으로 데이터 수집), Crawl(웹사이트 전체 URL 스크래핑), Map(사이트의 모든 URL 발견), Batch Scrape(대량 URL 비동기 처리)가 있습니다. JavaScript 렌더링 페이지를 포함해 96%의 웹을 지원하며, P95 지연시간 3.4초의 성능을 제시합니다. 프록시 로테이션, 속도 제한 관리, JS 차단 콘텐츠 처리 등을 자동으로 처리합니다. Python, Node.js, Go, Java, Elixir, Rust, Ruby, .NET, PHP SDK를 제공하며, Claude Code, Antigravity 등의 AI 에이전트와 MCP(Model Context Protocol) 클라이언트와 통합됩니다.

**어디에 쓰나**

AI 에이전트와 챗봇의 실시간 웹 데이터 소싱(검색 결과를 구조화된 데이터로 변환하여 LLM에 전달), 웹 기반 자동화(e-커머스 사이트에서 상품 검색 및 클릭, 양식 작성 등), 대규모 웹 크롤링(경쟁사 모니터링, 시장 조사, 가격 추적), 문서 추출(웹 호스팅 PDF, DOCX 파싱), 데이터 리서치 및 수집(특정 정보를 찾기 위해 여러 웹사이트 탐색), API가 없는 웹 서비스의 데이터 접근. 적합한 사용자는 AI 에이전트/챗봇 개발자, 데이터 과학자, 자동화 엔지니어, 웹 크롤링이 필요한 SaaS 기업입니다.

**살펴볼 점**

AGPL-3.0 라이선스로 배포되며 클라우드 버전(firecrawl.dev)은 추가 기능 포함. 로컬 실행 또는 자체 호스팅을 원하면 기여 가이드/자체 호스팅 가이드 참고. 기본적으로 robots.txt 지침을 준수하며, 사용자는 웹사이트 정책과 이용약관을 준수할 책임이 있음. API 키 필요(firecrawl.dev에서 가입).
