# 직군별 추천 공통 섹션 설계 (2026-07-31)

## 배경

현재 뉴스레터는 각 레포의 `roles`를 직군별로 역집계한다. 한 레포가 여러 직군에 적합하면 같은 레포와 추천 이유가 직군별 목록에 반복되어 추천 섹션이 길어지고 핵심을 파악하기 어렵다.

## 결정 사항

- 유효한 `roles`가 2개 이상인 레포는 `🌐 공통` 목록에 한 번만 표시한다.
- 공통 목록으로 이동한 레포는 개별 직군 목록에서 제거한다.
- 유효한 `roles`가 정확히 1개인 레포만 해당 직군 목록에 표시한다.
- 유효한 역할이 없는 레포는 현재처럼 추천 섹션에 표시하지 않는다.
- `🌐 공통`은 `👥 직군별 추천` 아래에서 개별 직군보다 먼저 표시한다.
- 레포 순서와 `recommendReason`은 기존 값을 유지한다.
- 기존 아카이브는 변경하지 않고 이후 생성되는 뉴스레터부터 적용한다.

## 구현 범위

### `src/render.mjs`

`renderRoleRecommendations`에서 입력 항목을 먼저 공통 추천과 단일 직군 추천으로 분류한다.

1. `roles`에 유효한 직군 ID가 2개 이상이면 공통 추천으로 분류한다.
2. 유효한 직군 ID가 정확히 1개이면 해당 직군 추천으로 분류한다.
3. 공통 추천이 있으면 `- **🌐 공통**`과 그 하위 레포 목록을 먼저 출력한다.
4. 각 직군에는 단일 직군 추천만 출력하고, 추천이 없는 직군은 계속 생략한다.

요약 데이터 스키마와 LLM 프롬프트는 변경하지 않는다. 공통 여부는 이미 정규화된 `roles`를 이용해 렌더링 단계에서 결정한다.

## 출력 예시

```markdown
## 👥 직군별 추천

- **🌐 공통**
  - [owner/shared](https://github.com/owner/shared) — 여러 직군이 함께 활용할 수 있다.
- **🧑‍💻 프론트엔드**
  - [owner/frontend](https://github.com/owner/frontend) — 프론트엔드 작업에 유용하다.
```

`owner/shared`가 프론트엔드와 백엔드 역할을 모두 갖더라도 두 개별 직군에는 다시 나타나지 않는다.

## 오류 및 경계 조건

- `roles`가 없거나 배열이 아니면 역할이 없는 항목으로 취급한다.
- 알 수 없는 역할 ID는 공통 판정과 직군 출력에서 제외한다.
- 같은 역할 ID가 중복되어 있어도 하나의 유효 직군으로 계산한다.
- 공통 또는 특정 직군에 추천 항목이 없으면 해당 목록 제목을 출력하지 않는다.

## 테스트

렌더러의 최종 Markdown을 기준으로 다음 동작을 검증한다.

1. 서로 다른 유효 직군이 2개 이상인 레포는 공통 목록에 정확히 한 번 나오고 개별 직군에는 나오지 않는다.
2. 유효 직군이 1개인 레포는 해당 직군에만 나온다.
3. 역할이 없는 레포는 추천 목록에서 제외된다.
4. 중복된 동일 역할 또는 알 수 없는 역할은 공통 판정 개수를 부풀리지 않는다.
5. 공통 추천이 없을 때 `🌐 공통` 제목은 출력되지 않는다.

## 제외 범위

- 기존 아카이브 소급 수정
- LLM 응답 스키마 또는 프롬프트 변경
- 추천 이유를 직군별로 다시 생성하는 기능
- 디스코드 메시지 형식 변경
