# 간결한 뉴스레터 콘텐츠 형식 설계

## 배경

README 전체를 근거로 상세 분석하도록 바꾼 뒤, LLM이 설치 방법·지원 도구·제약사항을 과도하게 나열해 레포별 본문이 길어졌다. archive의 `무엇인가`, `어디에 쓰나`, `살펴볼 점`은 굵은 글씨로만 표시돼 섹션 경계가 약하고, 짧은 핵심 설명과 본문 내용도 반복된다.

## 목표

- 레포를 이해하는 데 필요한 핵심 내용만 남긴다.
- 본문 섹션을 Markdown 헤더와 아이콘으로 명확하게 구분한다.
- 활용 사례를 빠르게 훑을 수 있는 짧은 불릿으로 표시한다.
- `살펴볼 점`과 `considerations`를 데이터 모델과 모든 출력에서 제거한다.
- daily와 weekly의 archive 및 Discord에 같은 콘텐츠 정책을 적용한다.

## 요약 데이터 모델

레포별 요약은 다음 세 필드만 사용한다.

- `koDescription: string`: 레포의 정체성을 설명하는 한 문장
- `summary: string`: 해결하는 문제, 핵심 기능, 차별점을 담은 짧은 문단
- `useCases: string[]`: 구체적인 사용 주체와 상황을 담은 2~4개 짧은 활용 사례

`considerations`는 제거한다. 설치 방법, 지원 도구 전체 목록, 세부 옵션, README 목차 재진술은 프로젝트의 정체성을 이해하는 데 반드시 필요할 때만 `summary`에 포함한다. 같은 사실을 `koDescription`, `summary`, `useCases`에서 반복하지 않는다.

## LLM 작성 규칙

- README 전체는 계속 분석 근거로 사용하며 입력을 자르지 않는다.
- README 내용을 빠짐없이 요약하려 하지 말고 의사결정에 필요한 핵심만 선택한다.
- `summary`는 하나의 짧은 문단으로 작성한다.
- `useCases`는 2~4개만 선택하고 각 항목은 `사용 주체 — 구체적인 활용 상황` 형식의 짧은 문장으로 작성한다.
- 확인되지 않은 기능이나 사용 사례는 추측하지 않는다.
- 설치 명령, 지원 도구 이름, 제약사항을 장황하게 나열하지 않는다.

문자 수 제한은 두지 않는다. 간결성은 항목 수와 작성 지침으로 유도한다.

## Archive 출력

각 레포는 다음 순서로 표시한다.

```markdown
> 한 줄 핵심 설명

### 🔎 핵심

프로젝트의 정체성, 해결 문제, 핵심 기능을 담은 짧은 문단.

### 🎯 활용 사례

- 개발팀 — 구체적인 활용 상황
- 운영팀 — 구체적인 활용 상황
```

기존 `무엇인가`, `어디에 쓰나`, `살펴볼 점` 라벨은 사용하지 않는다. `summary` 또는 `useCases`가 비어 있으면 해당 섹션 전체를 생략한다. 기존 제목, 트렌드 흐름, 레포 메타데이터, 출처와 구분선은 유지한다.

## Discord 출력

상위 5개 레포 정책과 4,096자 플랫폼 제한은 유지한다. 각 레포에는 한 줄 핵심 설명 대신 `summary`를 표시하고, 활용 사례는 앞에서부터 최대 2개만 불릿으로 표시한다. archive 링크는 항상 보존한다. 외부 분석 텍스트의 백틱 제거도 유지한다.

## 오류 처리

README 조회, LLM 요청, JSON 파싱 실패 시 현재 레포 단위 fallback과 다음 레포 계속 처리 동작을 유지한다. fallback 데이터는 `koDescription`, `summary`, 빈 `useCases` 배열로 새 스키마를 만족한다. 오류 응답이나 README 내용은 로그에 출력하지 않는다.

## 테스트와 완료 기준

- LLM 응답의 `useCases`가 문자열 배열로 정규화되고 비문자열·빈 항목은 제거된다.
- `considerations`가 LLM 결과에 포함돼도 최종 Summary에서 제거된다.
- archive에 `### 🔎 핵심`과 `### 🎯 활용 사례`가 나타난다.
- archive와 Discord에 `무엇인가`, `어디에 쓰나`, `살펴볼 점`이 나타나지 않는다.
- archive 활용 사례는 불릿으로 표시된다.
- Discord는 활용 사례를 최대 2개만 표시하고 4,096자 제한과 archive 링크를 유지한다.
- 기존 README 무제한 입력, Anthropic 잘림 처리, 레포 단위 fallback 테스트가 계속 통과한다.
- 전체 `npm test`가 통과한다.

기존 archive 파일은 과거 기록으로 유지하며 수정하지 않는다.
